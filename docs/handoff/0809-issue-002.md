## Bug 修复记录 (用户修复)

### Bug 1: 工具名净化 (`sanitizeName`)

**症状**: `createUeToolExecutor` 使用净化后的工具名（`.` → `_`）调用 UE MCP，导致全部 218 个工具返回 "tool not found"。

**根因**: UE 工具名含点号 (`toolset_registry.toolsets.core.scene.SceneTools.find_actors`)，Pi/LLM 要求 `^[a-zA-Z0-9_-]+$`，不含点号。

**修复**:
- `PiToolRegistration` 新增 `ueName` 字段（存原始名）
- `name` 字段存净化名（`. → _`），用于 `pi.registerTool()` 和 LLM
- `createUeToolExecutor` 使用 `ueName` 调 `ueClient.callTool()`
- 记忆: `[[pi-tool-name-sanitization]]`

### Bug 2: SDK callTool 签名

**症状**: SDK v1.30.0 的 `callTool` 签名与 v1.0.x 不同，需三个参数。

**修复**: `client.callTool({name, arguments}, undefined, { signal })` — 第二个参数 `undefined`（无 `RequestOptions`）。

### Bug 3: import 路径扩展名

**症状**: `compile-schemas.ts` 无法 import TypeScript 源文件。

**修复**: 使用 `.ts` 扩展名（配合 `tsx` 运行时）。

## 决策记录

- **D6**: UE 不使用 oneOf/anyOf/$ref → converter 无需处理（PRD 风险已消除）
- **D7**: 工具名净化在 `convertTool` 中统一执行，`createUeToolExecutor` 中统一用 `ueName`
