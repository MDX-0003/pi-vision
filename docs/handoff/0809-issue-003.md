## Bug 修复记录

### Bug 4: Vision API 格式假设导致 404

**症状**: `POST .../compatible-mode/v1/v1/messages → 404`

**根因**: 代码假设所有 Vision API 为 Anthropic 格式，无条件追加 `/v1/messages`。
用户 baseUrl 已是 `.../compatible-mode/v1`（阿里云兼容模式），导致双 `/v1`。

**修复**: VisionClient 构造函数检测 baseUrl：
- 以 `/v1` 结尾 → OpenAI 格式 (`chat/completions`, `Authorization: Bearer`)
- 否则 → Anthropic 格式 (`/v1/messages`, `x-api-key`)

### Bug 5: sharp + tsx 大图静默失败

**症状**: `npx tsx -e "import sharp; ..."` 处理 9MB JPEG 时完全无输出（无错误/无超时/无 exit code）。

**根因**: tsx ESM loader 在处理大 buffer 的 import/await 链时有静默失败。

**修复**: 绕过 tsx——使用已缓存的 CaptureViewportImage PNG(1.7MB, 1280px cap) 或 `node --input-type=module`。
VisionClient 内部不做 resize（由 capture.ts 的 CaptureViewportImage 保证 ≤ 1280px）。

**记忆**: `[[vision-api-format-detection]]`

## 决策记录

### D8: Vision API 双格式自动检测

**决定**: VisionClient 根据 `visionApiBaseUrl` 自动选择 API 格式:
- baseUrl 以 `/v1` 结尾 → OpenAI Chat Completions 格式
- 否则 → Anthropic Messages API 格式

**原因**: 用户使用阿里云兼容模式的 Qwen 模型，API 为 OpenAI 兼容格式。Arbitrary 选择 Anthropic 作为默认是因为市面上最多的 vision provider 使用此格式。

### D9: Vision Auth 文件存储

**决定**: Vision API key 存储在 `~/.pi/agent/vision-auth.json`，与 Pi `auth.json` 平行管理。

**格式**:
```json
{ "apiKey": "...", "baseUrl": "...", "modelId": "..." }
```

**加载优先级**: 环境变量 > vision-auth.json > 默认值

### D10: 量化指标计算加速

**决定**: 指标计算前将图片 resize 到 512px（luminance/saturation/R-B 比）和 64px（直方图相关），大幅加速计算 (<10ms)。

## 已知限制

1. **Vision 一致性**: 同一图片多次评分的 rating 可能有 ±1 波动。gap 判定用硬编码阈值 (`|diff| ≥ 3 → major, = 2 → moderate, ≤ 1 → minor`) 而非 LLM 直接输出，已缓解
2. **artificiality 检测**: 基于单一规则（"受光面色温 vs 阴影色温是否一致"）→ 后续 Issue 005 可增强为 color-diagnostics 的 7 种决策树
3. **图片大小**: 截图 1.7MB → base64 2.4MB → + Vision prompt → ~2600KB。Qwen 模型接受。如果换模型可能需调整 resize 策略
