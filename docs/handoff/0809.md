**UE 工具集加载流程**：
1. `tools/list` 初始返回 3 个引导工具 (`list_toolsets`, `describe_toolset`, `load_toolset`)
2. `list_toolsets` → 返回纯文本格式的工具集列表（20 个）→ 正则解析：`/^\s*-\s*(\S+):/gm`
3. 逐个 `load_toolset` → 加载完成后 `tools/list` 重新查询 → 216 个工具

**已确认的 UE MCP 参数规范**（对 Issue 002 的 Schema 转换至关重要）：

```typescript
// get_properties: instance 是 refPath 对象，properties 是字符串数组
{ instance: { refPath: "/Game/.../ActorName.ComponentName" }, properties: ["LightColor", "Intensity"] }

// set_properties: instance 同上，values 是 JSON 字符串（不是裸 object）
{ instance: { refPath: "/Game/.../ActorName.ComponentName" }, values: '{"LightColor":{"R":0.5,"G":0.3,"B":0.1}}' }

// find_actors: tag 是必填字段（即使为空字符串），glob 默认 "*"
{ glob: "*DirectionalLight*", tag: "" }

// CaptureEditorImage: 无参数，返回 { returnValue: { mimeType: "image/png", data: "base64..." } }
```

**组件属性访问**：`LightColor` 不在 Actor 上，在子组件上。需要两步解析：
1. `get_properties(actorRefPath, ['directionalLightComponent'])` → `{"directionalLightComponent":{"refPath":"/Game/.../DirectionalLight_0.LightComponent0"}}`
2. `get_properties(componentRefPath, ['LightColor'])` → `{"LightColor":{"r":1,"g":1,"b":1,"a":1}}`

**截图稳定性**：`CaptureEditorImage` 需要 UE 编辑器有一个打开且有焦点的视口。从 harness 文档确认：该工具是同步截图，不依赖 viewport screenshot delegate。失败时返回 `"Failed to capture any editor windows."`。

## 2. 关键决策记录

### D1: 工具交互策略

**决定**：使用 `@modelcontextprotocol/sdk` 的 `Client` + `StreamableHTTPClientTransport`，不使用手写 JSON-RPC。

**原因**：
- SDK 处理 SSE 解析、session 管理、重连逻辑
- 只需 ~30 行配置代码 vs Python harness 手写的 ~600 行 `client.py`
- 参数透传：UE 工具的所有参数保持原名（`instance` 不是 `actor`，`values` 不是 `property_value_json`）

### D2: 组件属性发现

**决定**：在 `map_atmosphere` 工具中实现 Actor → Component 的 refPath 解析逻辑。

**原因**：UE 的 `LightColor` / `Intensity` 等光照属性在组件上不在 Actor 上。直接让 LLM 处理这个两步跳转会出错。工具内部应透明处理。

### D3: CaptureEditorImage 返回格式

**决定**：将 `returnValue.data` (base64) 转为 `Buffer` 使用，不作为 MCP `image` content block。

**原因**：UE MCP Server 将所有返回封装为 `{"returnValue": {...}}` JSON，不直接返回 MCP 协议的 image content。SDK 侧收到的是 text content block。需要额外解析 `returnValue.data`。
